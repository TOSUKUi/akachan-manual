# Scope: あかちゃんマニュアル（品川区向け赤ちゃんガイド）

東京都品川区在住の男性予定者向けに、出産当日から 2 歳までの育児知識と手続きをまとめた静的サイト。9 章構成、全事実に元ソースリンクを付ける。姉妹サイト shinagawa-hojokin（給付・助成）と分業。

**Build approach:** Tracer Bullet（薄いエンドツーエンドのスライスから作り、太くしていく）。
**Workflow:** Beta（develop 後に check verify、続いて test）。プロジェクト全体のデフォルトの厳格さ。`/architect` は本格的な判断がある機能の最初の行き先だが、作り方が分かっているなら飛ばしてよい。機能ごとにタグ（例: `· GA`）で厳格さを上げ下げできる。

_これらはビルドを整えるための推奨であり、強制ではない。合わないものは飛ばしてよい: 機能の作り方が分かっているなら `/architect` を飛ばして `/develop` を使え。`done` とする判断はあなたがする。_

## Legend

**決定ボックス.** 各機能にちょうど 1 つある。ラベルが `(spec)` で終わるサブタスクのこと。表記は機能によって変わる（通常は `設計する（spec）`、スタックとアーキテクチャでは `スタックを決める（spec）`）。スキルはこの `(spec)` 接尾辞で特定し、正確なラベルには依存しない。他のボックスはすべて実行ボックスで、`/architect` は決してチェックしない。

**機能のライフサイクル**: 機能が動くと scope も更新される。各行の状態と、それを設定する者:

| 状態 | 設定者 | 機能の表示 |
|---|---|---|
| `planned` · 判断が必要 | `/scope` | 1 つのボックス: `設計する（spec）: /architect <機能>` |
| `in-progress`（設計済み） | **`/architect` が spec を取得した時** | `設計する` にチェック、spec リンク、`作る: /develop <機能>` + **2〜5 のマイルストーン**、ティアの仕上げボックス（`検証する` は Alpha 以上、`テストする` は Beta 以上、`レビュー` + `ドキュメント` は GA）、surfaced な follow-up の登録 |
| `in-progress`（実装中） | `/develop` | マイルストーンのサブボックスが順にチェック、コードポインタが入る |
| `in-progress`（検証済み） | `/check verify` | `作る` + マイルストーンにチェック、`検証する` にチェック |
| `done` | **あなたが判断した時**（どのスキルでも指示があれば設定）。`/sync` が調整 | 実行したボックスにチェック、スキップしたものはスキップ表示。ティアの最終段階（`Prototype` → `/develop` 後、`Alpha` → `/check verify` 後、`Beta`/`GA` → `/test` 後）が done とすべき推奨時点。`/sync` が規約を捕捉 |

- **次の一手** = 最初の未チェックボックス（常にコマンドまたは追跡マイルストーン）
- **判断が必要** = 先に `/architect` を実行。それ以外はそのまま `/develop`（規約とツール類は `/audit`）。spec が取得されるとタグは消える
- **アトミックなビルドタスクは spec の `## Build plan` にあり、ここには無い**: scope はマイルストーンの要約だけを持つ
- **ステータス** `planned` → `in-progress` → `done`、加えて `existing`（ワークフロー以前）と `dropped`（スコープ外、履歴保持）
- **アプローチタグ**（見出し横、例: `· Facade`）はプロジェクトデフォルトをその機能だけ上書き。タグ無しは継承
- **ワークフローティアタグ**（見出し横、例: `· GA`、`· Prototype`）はその機能だけの厳格さをデフォルトから上下する。タグ無しはデフォルトを継承。チェックボックスと各スキルの次の提案を決める
- **Workflow**（ヘッダー行）はプロジェクトデフォルトで、`/develop` の後に何を実行するか: **Prototype** = 何もしない（develop 自身のビルド時セルフチェックに頼る）、**Alpha** = `/check verify`、**Beta** = `/check verify` 続けて `/test`、**GA** = フレッシュモデルの `/check review` 続けて `/document` を追加。未承認の判断（`Assumed` spec）の上に作られた機能はフラグが残るが、それは `done` をブロックしない
- **ポインタ行**（`spec <n> · code in <path>`）: `/architect` が追加する spec リンク、`/develop` が追加するコードパス
