## 方法（必ず守る）

1. 公式ページを特定するため `web_search` を使う（迷ったら必ず検索する。憶測で URL を書かない）。
2. ページ本文を読む（fetch/browser/snapshot）。**検索スニペットや自分の記憶だけで書かない。**
3. **実際に開いて内容を確認した URL だけ**を根拠に使う。
4. 数値・期限・年齢はページ本文の原文と照合して書く。
5. 公式ソースが見つからない事実は書かない（末尾 Gaps に書き出す）。

```markdown
## <H2 セクション見出し>

必須: [<canonical-id>]   ← この章に割り当てられた canonical ID をカバーするセクションの末尾に

### <H3 小見出し（任意）>

<本文>
根拠: [ソース略名](<URL>)
```

### フォーマット規則（ビルドゲートが検証するので必ず守る）

- 冒頭文と全 H2/H3 セクションに**最低 1 行** `根拠: [ソース略名](URL)` が必要
- `根拠:` に使った URL は**全て** frontmatter の `sources[]` に name と url で登録されていること
- frontmatter の `must` 配列 == 本文中の全 `必須: [id]` の ID の集合（一致させる）
- `必須: [id]` は行単独で、事実の直後に置く。`id` は小文字ハイフン
- 見出しは `##` / `###` のみ（`#` は使わない。frontmatter の title が章タイトル）
- 日本語、敬体。医療アドバイスではなく「こういう推奨が公式にあり、出典はこれ」と記述する
- ファイル末尾に `## Gaps` セクション（裏取れなかったこと・要注意点）を付ける。このセクションも `根拠:` 行が要らない（後で私が処理する）

### 注意

- `## Gaps` 以外のセクションは全て `根拠:` 行が必要
- 1 セクションに 1 つの `根拠:` 行で足りる（複数の URL を並べる場合は 1 行に複数 [name](url) をカンマ区切りで）
- 品川区特有の電話番号・窓口・申請期限は必ず品川区公式ページから
